# 设计

## D-A1 · 读版本不起进程 —— 这是本变更最重要的一条

四个 agent 走 npm，版本就写在它们自己的 `package.json` 里；grok 是独立二进制，
版本写在它自带的 `CHANGELOG.md` 首行。**全部是文件读。**

```
可执行文件（resolveCommand 已经解析出来了）→ 往上走 → 第一个带 version 的 package.json
                                          ↘ 找不到 → 第一个 CHANGELOG.md 的首行
```

**为什么不跑 `<agent> --version`**：因为不用。而「不起 agent 进程」不只是快 ——
这个项目最贵的一次事故就是探针碰了 agent 的 TUI：`/help` + 回车在 codex 的升级对话框上
选中了「立即更新」，把 codex 卸掉重装（`prototype-terminal-fidelity/findings.md:130-137`）。
grok 的二进制里同样有 `Update now? [Y/n/d]`，是同一类地雷。

> **能用读文件回答的问题，就不要用起进程去问。**

**对应的断言不是「跑得快」。** 原来写的是「耗时 < 500 ms」当旁证 —— 那既是间接证据，
又在并发套件里量的是调度不是代码（单独跑 280 ms，全套件里 606 ms，翻红过一次）。
改成**记下所有起过的子进程**，断言里面只有 `where.exe`：

```
起过的子进程：where.exe claude / where.exe codex / where.exe opencode / where.exe pi / where.exe grok
```

### 一个必须注意的细节

要往上走的是 **`args[0] ?? exe`**，不是 `exe`。codex / pi 的 shim 走 node 跑一个 `.js`，
这时 `exe` 是 node 自己，往上走只会找到 node 的目录 —— 真正的包在脚本那一侧。

## D-A2 · D-8 的判据被这一刀修正了

D-8 原本是二分法「本地 / 内容出境」，判的其实是**有没有出网**。版本检查证明它不够用：
它出网，而出去的字节里**一个用户的字都没有**（就是一个包名，去问公共 registry 最新版号）。

把它和「把你的源码片段发给第三方模型」放进同一档，等于让 opt-in 失去分辨力 ——
什么都要问一遍，用户就什么都不看了。

> **修正后的判据：出去的字节里有没有用户的东西。**
> 有 → 必须 opt-in；没有 → 可以默认开，但要在界面上说清楚发的是什么。

「读本机装了什么版本」连网都不出，和「检测装了哪些 agent」同性质，不设开关。

## D-A3 · 判断「有新版」宁可漏报不可误报

自己写 `isNewer`，零依赖 —— semver 那个包的范围 / 通配 / satisfies 一个都用不上。

**解析不了就返回 false。** 这条比「判得准」更重要：误报会把用户推去做一次没必要的升级，
而这个产品已经亲手弄坏过一次 codex。

必测的那条是 **`1.0.4` vs `0.2.118`**（grok 本机的真实情况）：
逐段按字符串比会被 `118 > 4` 骗过去，必须按数字比，且**高位一分胜负就返回**。

## D-A4 · 链接从 registry 元数据推，推不出就不给

| agent | 来源 | 结果 |
|---|---|---|
| claude | `homepage` | ✓ |
| codex / pi | `repository.url` | ✓ |
| opencode | 两个字段**都没有**（实测确认） | **不给按钮** |
| grok | 不在 npm，`x.ai/cli/changelogs` 等路径实测全 404 | **不给按钮** |

**不写死 URL** —— 烂掉的链接比没有链接更糟。那两行照常显示版本号与更新命令。

主进程侧对 `agents:openReleases` 只放行 `^https://github\.com/[\w.-]+/[\w.-]+/releases$`，
不接受渲染层传任意 URL。

**坑**：npm registry 的缩略元数据 accept 头（`application/vnd.npm.install-v1+json`）
对 **scoped 包**的 `/latest` 返回 **406**。`opencode-ai` 能过，三个 scoped 包全挂。用默认 accept。

**grok 的端点**从它自己的安装脚本 `https://x.ai/cli/install.ps1:150-176` 挖出来：
`$BaseUrlPrimary/$Channel` → `https://x.ai/cli/stable`，返回一行纯版本号。

## 实现时踩到的两个坑

**① 齿轮小圆点靠推送会丢。** 主进程在 app-ready 时就查完并 `send`，
那时渲染层还没开始监听 —— 实测 `齿轮有小圆点: false`。
改成**渲染层启动时自己拉一次**（缓存命中的常见情况），推送只负责「启动之后才查完」那一种。

**② 五行的列对不齐。** 每一行各自是 flex 容器，列宽互不相干，
「看更新说明」在五行里落到了四个不同的横坐标（截图确认）。
改成**写死宽度的四列 grid**，且四个格子永远都在（空的也占位）——
少一个格子，后面的列就整体左移。

> 这两个都是**截图**才发现的。冒烟输出全绿不等于界面对。
