# 字号与字体

> **纪律：先复现，再修。** 每一条都有「修之前是什么样」的实际输出。

## 1. 复现

- [x] 1.1 用 `sendInputEvent` 而不是 `dispatchEvent` —— **整页缩放在输入管线里处理，
      渲染层合成的 KeyboardEvent 触发不到它**，那样测出来的「没缩放」是假的
      ```
      [smoke-zoom-start] zoomFactor=1
      [smoke-zoom-minus] 按了 3 次 Ctrl+- 之后 zoomFactor=0.76
      [smoke-zoom-plus]  再按 3 次 Ctrl+= 之后 zoomFactor=0.76   ← 放大那半没绑上
      ```
- [x] 1.2 根因：代码里**零处**设置 `zoomFactor` —— 那是 Chromium 自带的，我们从没要过

## 2. 缩放键改绑到终端字号

- [x] 2.1 `Ctrl+= / Ctrl+- / Ctrl+0`，主键盘与小键盘都认。
      `Shift` 不参与判断 —— 主键盘打 `+` 就是 `Shift+=`
- [x] 2.2 写进 `SHORTCUTS`（唯一真源，F1 面板从它读），并在表里说清
      **为什么这三个是「全部走 Ctrl+Shift」原则的例外**
- [x] 2.3 验收：`zoomFactor` 全程 1，而终端字号 **13 → 10 → 13**（读的是 xterm
      实例上的真实值，不是我们自己的 state —— 「存下了」和「用上了」是两件事）
- [x] 2.4 F1 面板从 11 条变 14 条；`裸 CtrlW 未被截走: true`（没误伤终端的键）

## 3. 字号设置

- [x] 3.1 `Settings` 加 `uiFontScale` / `termFontSize` / `termFontFamily`，
      **范围在主进程夹** —— 设置文件用户会手改，一个 0 或 400 会让界面点不着
- [x] 3.2 CSS 五个字号档全部乘 `--ui-font-scale`（各写一套 = 五个会走散的决定）
- [x] 3.3 `--side-w` 也跟着乘 —— 截图显示特大时文字在固定宽度里折成四行，
      **字变大而容器不变只是把问题挪了个地方**
- [x] 3.4 顺带删掉 `--t-xl`：定义了但全仓库零处引用
- [x] 3.5 新面板出生时就用当前字号，不是先按默认排一遍再改（那一瞬间 agent 收到的行列数是错的）
- [x] 3.6 改完必须 `fit.fit()` —— 字号变了每格像素尺寸就变了

## 4. 终端字体族

- [x] 4.1 只给终端，界面不给（界面是系统字体栈，换掉基本只能把布局弄歪）
- [x] 4.2 **只列本机真装了的**（canvas 量宽度探测）。写死一串名字的话，
      用户选了个没装的会静默退回，看起来像「选了但没生效」
- [x] 4.3 本机探测结果：`Cascadia Mono | Cascadia Code | Courier New |
      Lucida Console | MS Gothic | NSimSun`（14 个候选里 6 个装了且等宽）

## 5. 一个我自己建错又删掉的东西

- [x] 5.1 第一版还量了「CJK 是不是恰好双宽」并标 ⚠。实测 6 个里 4 个「非双宽」，
      **包括我们自己的默认 Cascadia Mono** —— 而用户拿它跑的中文表格是**对齐的**
- [x] 5.2 去核实机制：**xterm 按格子排版**，宽字符固定占 2 格，glyph 画在那 2 格里，
      窄了留白宽了裁掉，**下一格起点不变**。表格不会错位，差别只在字形挤或松
- [x] 5.3 在默认字体旁边挂一个基于错误因果的警告 = D-W1 禁止的那件事。整块删掉
