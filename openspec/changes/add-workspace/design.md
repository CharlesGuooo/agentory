## Context

三根支柱里，「重启恢复」是用户排第一的痛点，到目前为止**一点都没解**。
前置条件都齐了：索引（437 会话）、`resumeCommand`（五套已验）、多终端与标签页。
缺的只是把「我在用哪些会话」记下来。

## Goals / Non-Goals

**Goals:**
- 工作集：成员资格只由显式动作改变，持久化，重启后完好
- 批量恢复：串行、后台、带进度、失败不中断
- 关掉应用再打开，能把上次那批会话放回来

**Non-Goals:**
- 会话摘要（D-7）、opt-in 扫描流程（D-8）
- 恢复正在运行的会话（`add-session-resume` 的 Open Question，仍未解）
- 「移出工作集但保持运行」——见 D-W2

## Decisions

### D-W1 · 工作集记的是恢复所需的最小信息，不是索引记录的副本

存 `{ agent, sessionId, cwd, addedAt }`。**不存** `lastActivity` / `nativeTitle` 这些索引字段 ——
它们会过期，而工作集的职责是「记住你在用哪些」，不是「缓存索引」。
需要新鲜信息时去扫（339 ms，D-4 已定不建缓存）。

### D-W2 · Q7 定案：「结束会话」= 杀进程 + 移出工作集

只移出不杀，会留下一个**界面上看不见、却还在烧资源**的孤儿进程 ——
而用户的机器上单是 8 个 claude 就有上百个子进程。

「移出工作集但保持运行」这个需求目前不存在，不做。名字叫「结束会话」，做的就该是结束。

### D-W3 · D-12 的字面做法被否决，按其精神实现

D-12 原文：「建好 tab、把 `claude --resume <id>` 打进终端，但不回车」。

**做不到而不引入问题**：PTY 必须托管一个进程，要「打字不回车」就得先起一个 shell。
那个 tab 托管的就成了 shell 而非 agent —— pid、退出码、状态追踪全部对不上，
`onExit` 收到的是 shell 的退出而不是 agent 的。

**改为**：tab 以「未启动」状态存在（没有 PTY），显示将要执行的完整命令，点一下才真起。
效果一致（不自动烧 token、多一次确认），且不引入一个假的 shell 层。

### D-W3b · （实现期发现）新建的会话拿不到 id，改用「继续最近」

写界面时才撞到：**agent 的会话 id 是它自己生成并写进会话文件的，spawn 那一刻拿不到。**
而原规格假定工作集条目一定有 `sessionId`。

**被否决的方案**：事后扫描索引、按 cwd + 时间反查 id。
有竞态（agent 什么时候写文件不确定）、要择时（何时扫）、还要处理匹配歧义。

**采用**：`sessionId` 允许为 null，这类条目用五个 agent 都支持的
「继续该目录下最近的会话」（`claude -c` / `codex resume --last` / `opencode -c` / `pi -c` / `grok -c`）。

**已知代价**：若用户在同一目录用 agentory 之外的方式又开过会话，`-c` 会接到那一个。
可解释、可接受 —— 而反查方案的失败模式（接到错误的会话）是一样的，只是更复杂。

### D-W4 · 串行恢复用简单的顺序 await，不建作业队列

同 D-13 的精神。恢复是**不跨重启**的一次性动作（子进程随应用消亡），
不需要持久化进度，也就不需要队列 —— 一个 `for` 循环加一个进度回调就够。

### D-W5 · 每次变化立即落盘，不做防抖

工作集变化是低频的（用户点新建/结束时才变），一次写入几百字节。
防抖会引入「崩溃时丢最后一次变化」的窗口，而那恰恰是这个功能存在的理由。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 工作集里的会话 id 在 agent 侧已被删除 | 恢复时 agent 自己会报错；界面按「恢复失败」展示并保留该成员，由用户决定是否结束它 |
| 批量恢复期间用户关掉应用 | 规格已定：不跨重启续做。子进程随应用消亡，续做无意义 |
| 「未启动」状态是第四种状态，界面要多认一档 | 三态（工作中/等你输入/已停）本就存在，加一档「未启动」；用不同的呈现而非新颜色，避免色彩语义膨胀 |
| 又一段没有自动化测试的界面 | 纯逻辑（成员资格、持久化解析、批量编排）严格 TDD；界面走已有的冒烟点击路径 |

## Open Questions

- 恢复失败的成员要不要自动移出工作集？**倾向不** —— 失败可能是临时的（agent 没装、目录暂时不可达），
  自动移出等于替用户丢东西。
- 工作集要不要有上限？暂不设。真出现几百个成员时再谈，那时的问题多半是别的。
