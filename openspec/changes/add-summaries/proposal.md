# 会话摘要（D-7 第 1 层）

## 为什么

DESIGN.md §1 立的三支柱里，**摘要是唯一原创的那个**，也是唯一没做的：

| 支柱 | 状态 |
|---|---|
| 重启恢复（第一痛点） | ✓ `add-workspace` |
| **会话摘要（全网无人做）** | **本变更** |
| 跨 agent 统一切换 | ✓ `add-session-index` / `add-app-shell` |

`add-favorites` 已经把「第二行显示什么」做成了一条优先级链：

```
摘要（未做） ?? agent 自带标题 ?? 首条有信息量的用户消息
```

第 0 层（首条有信息量的消息）实测可读率 **90.5%**，代码里到处写着「真摘要做出来前的**占位**」。
本变更把链首那一格填上。**界面代码一行不动** —— 这正是当初把它设计成链的目的。

## 调研得到的三个事实

**1. 模型 ID 变了。** `deepseek-chat` / `deepseek-reasoner` 两个别名**已于 2026-07-24 弃用**。
当前是 `deepseek-v4-flash`（1M 上下文）与 `deepseek-v4-pro`。两者都**默认开思考模式** ——
对一句话摘要是纯浪费，必须显式关掉。

**2. 成本不是约束。** v4-flash $0.14/M 输入、$0.28/M 输出，每条会话喂约 4 KB、出 30–50 字。
**摘完本机全部 437 条 ≈ $0.08。**

> 这让 D-8 的理由更清楚：opt-in 防的从来不是花钱，是**在用户不知情时把源码发出去**。
> 所以本变更的设计重心是**透明度**，不是成本控制。

**3. 价格 2026-08-16 起改峰谷计费**（谷时半价）。所以界面里的费用估算必须标注来源日期，
不能当成永久事实。

## 改什么

- 五个 agent 的消息提取**收口到一处**（`sessions/messages.ts`），头尾都从这里出
- 载荷构造：首条 prompt + **过滤掉工具输出的**尾部，整体封顶 4 KB
- DeepSeek 客户端（零依赖 `fetch`）、摘要缓存（`summaries.json`）、串行作业
- 设置里的摘要区块：开关（**默认关**）、API key、**「看看会发送什么」**、批量跑

## 不改什么

- **文件监听 / 实时摘要** —— 见 design.md，D-7 自己的论证不支持它
- **摘要的编辑与重写** —— 身份是 session id，意义是摘要，第三套命名早就否决过
- **多模型可选** —— 先只接 DeepSeek，真有第二个需求再抽接口（D-11 的精神）
- **成本上限 / 预算控制** —— 全量 $0.08，为它建预算机制是过度建造
- **opencode 的摘要** —— 它自带的 title 是模型生成的真标题，重做一遍是花钱买更差
