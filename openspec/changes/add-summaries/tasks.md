## 10. ponytail-review 的结果（已应用）

- [x] 10.1 `SummaryState.running` 没有任何读者 —— 删掉（主进程本来就自己挡重复跑）
- [x] 10.2 `payload.ts` 取两种角色再 `.filter(user)`，是 `preview.ts` 刚修掉的同一个反模式。
      角色推下去；顺带删掉 `HEAD_CANDIDATES=24` —— `pickInformative` 内部只看前 12 条，
      多要的 12 条纯浪费
- [x] 10.3 `SummaryState.price` 没有任何读者 —— 也就是说计划里的费用估算**根本没显示**。
      补上了，但**换了位置**：原先写在「点完之后的进度行」，那既会跟异步结果抢位置
      （冒烟实测被 `还没有填 API key` 盖掉），**又根本没用 —— 点完才告诉你要花多少不叫知情**。
      改成写在常驻状态行的「每条约 $X」，点之前就看得见，且不需要知道总数
- [x] 10.4 `summaryStop` 在 preload 里暴露着但**没有任何界面调用** ——
      不是删掉，是接上按钮：几百条串行跑十几分钟且在花钱，没有中止手段是缺陷
