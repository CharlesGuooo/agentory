# 设计

## Q9 定案（本变更实测关闭）

`DESIGN.md §2.6` 的注入表里 pi / opencode 两格是「待确认」。实测结果：

| agent | 首条用户消息的注入 | 实测样本 |
|---|---|---|
| **pi** | **无包装** | 首条就是原文（`你看下这个repo，知道它是干嘛的…`）。但会出现 `/help` 这类**斜杠命令**，等于没信息 |
| **opencode** | **无包装** | 首条就是原文；且 `session.title` 实测**可用**（`AI项目知识库整理规划`、`升级 opencode 到最新版本`） |

→ 过滤规则里为这两个 agent 加的不是「剥注入」，而是「跳过斜杠命令」。

## D-F1 · 第二行是一条优先级链，不是单一来源

```
摘要（D-7，未做） ?? agent 自带标题（只有 opencode 有） ?? 首条有信息量的用户消息
```

**为什么不统一用首条消息**：opencode 自带的 title 是模型生成的真标题，
质量高于原始首条消息。用更差的盖掉更好的，是为了「一致」牺牲用户能读到的信息。

**为什么 grok 的自带摘要不进这条链**：它是粗暴截断（`§2.6` 有原样证据），
比我们自己截还差 —— 「有」不等于「可用」。

摘要做出来后接在链首，界面代码一行不动。

## D-F2 · 「有信息量」是一条可测规则，不是感觉

按顺序取用户消息，逐条判断，取第一条通过的：

1. 剥掉 agent 各自的注入包装（`§2.6` 那张表）
2. 跳过斜杠命令（`/help`、`/init`…）
3. 压缩连续空白后**仍 < 20 字**的跳过 —— 实测失败样本全是这一类
4. 截断到 46 字

全部取不到就返回 `null`，界面显示「（没有可读的开头）」而**不是空白** ——
空白让人以为是加载中。

## D-F3 · 收藏条目的 `sessionId` 不可为空

与 `WorkspaceEntry` 的关键差别。工作集里的条目可以是「该目录下最近的会话」
（新建时拿不到 id，D-W3），而**收藏一定指向一个具体会话** —— 「以后还要用这个」
指的是那一个，不是那个目录里最新的那个。

所以主键是 `(agent, sessionId)`，不需要工作集那套 `?? cwd` 兜底。

代价：**在 agentory 里新建的会话收藏不了**（没有 id 可指）。如实记录，不假装没有。

## D-F4 · `label` 存快照，且这不违反 D-W1

D-W1 禁的是**会过期**的字段（`lastActivity` / `cwdExists`）。
首条用户消息是 append-only 历史里**不可变**的东西 —— 它永远不会变。

存下来换到的是：**启动时零文件读**。侧栏收藏区块要在启动时就渲染，
而扫描是 opt-in 的（D-8，默认关）—— 不存快照就只能现读文件或强制扫描，两者都更糟。

## D-F5 · 落盘复用工作集那层外壳，不复制一份校验

`favorites.json` 与 `workspace.json` 同在 userData，**同一种形状**
（`{version:1, sessions:[…]}`，带缩进，用户能直接打开手改）。

`workspace/store.ts` 里那层文件外壳抽成 `loadEntryFile(path, parseOne)`：
读 → `JSON.parse` → 逐条校验（**单条坏只跳过那条**）→ **失败绝不写回**。

抽这一层的目的不是"复用"这个词本身，而是让「绝不替用户销毁记录」这条已有的测试
**同时守住两个文件**。复制一份校验代码 = 那条测试只守住其中一个。

## D-F6 · 主键必须能穿过 DOM 属性

照 D-W4：主键要进 `data-key` 再读回来查找，`U+0000` 会被 HTML 解析改写成
`U+FFFD`，让交互静默失效。收藏这一刀新增两条这类路径（星标、收藏项），
所以：

- 主键无控制字符，有单元测试守着
- 所有属性插值走 `esc()`（路径里 `&` 合法，不转义同样失配）
- **加冒烟守门**：星标点击与收藏项点击都必须有自动化的点击路径覆盖 ——
  上一刀正是靠一条真机检查才发现这类 bug 是哑的
