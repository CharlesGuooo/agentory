# 收藏夹 + 会话预览行

## 为什么

现在只有两类会话：**工作集**（跨重启保留、可能在跑）和**历史**（扫出来的全部）。
缺一类：用户想留着以后用、但现在不跑的。

讨论中把问题的层级重新定位了一次，这决定了本变更的范围：

> **身份是 session id，意义是摘要。**

不该为「收藏」发明第三套命名。而摘要（D-7）**还没做**，所以本变更实际要解决两件事：
收藏夹本身，以及**所有会话行「第二行显示什么」**—— 后者是工作集 / 历史 / 收藏 /
恢复面板四处共用的问题，不是收藏夹独有的。

已定的呈现形式：**摘要就是标题，占行内第二行**，不藏在问号后面。
按用户的说法，摘要是唯一能读懂的那行字，它是主要信息；问号方案把主要信息
当辅助信息藏起来，而且没悬停之前列表无法扫视。

## 一个必须先摆出来的实测结果

过渡期用「首条用户消息」。本机 18 个最近 claude 会话截到 46 字的真实结果：
**约 11/18 能看出是什么，5/18 完全没信息** —— 失败的全部是开头很短那种
（`看这里的文件，理解我要做什么` / `pull一下最新的` / `====…`），真内容在第二条。

DESIGN.md §2.6 还有一条独立佐证：Grok 自带的 `session_summary` 就是首条消息的
粗暴截断，产出是 `"﻿Use brave web search to find out who won the"`（从句中切断，还带 BOM）。

**所以规则是「取第一条有信息量的」**，不是「取第一条」。这一行本来就是占位，
真摘要做出来后原地替换，不改界面代码。

## 改什么

- 侧栏加「收藏」区块；历史行点五角星加/取消收藏
- 五个 agent 的「首条有信息量的用户消息」提取，接进扫描
- 四处会话行统一加第二行 + 行内短 id
- 第二行走**优先级链**：`摘要 ?? agent 自带标题 ?? 首条用户消息`
  （opencode 自带的 title 实测可用，不该被更差的原始消息盖掉）

## 不改什么

- 历史弹窗的「只看收藏」过滤 —— 等有人抱怨再加
- 从工作集行收藏 —— 新建的会话没有 sessionId，收藏无从指向（D-W3 的已知缺口）
- DeepSeek 摘要本身 —— 独立的一刀（要 key、opt-in、后台作业、缓存文件）
- 收藏的分组 / 排序 / 重命名
