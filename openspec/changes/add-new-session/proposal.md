## Why

侧栏上那个「新建会话」按钮**是死的** —— 用户点击时发现的。

查下去性质比「忘接事件」更糟：`btnNew` 在整个代码库里只出现在 `index.html` 一处，
从来没有被接过事件；而 `add-app-shell` 的规格里**完全没有提到新建会话**。
我把 demo 的布局搬进真实应用时，把这个按钮一起搬了，却既没实现也没删。

**这是界面上的一个假承诺** —— 和「用假数据填满侧栏」是同一类错误，
而我恰恰在 `add-app-shell` 的规格里写了「不放假数据」的要求。规格审查没抓到，因为规格根本没提它。

更要紧的是：按 **D-8「默认从 0 开始，扫描是 opt-in」**，
**新建会话是会话进入应用的主要入口**。没有它，用户打开应用只能去翻历史。

## What Changes

- **新建会话选择器**：选 agent + 选工作目录，然后在新标签页里起会话
- **只列出本机真正装了的 agent** —— 列一个装不上的然后让它启动失败，等于又一个假承诺
- **目录输入带候选**：候选来自已有的会话索引（本机 437 条会话覆盖数十个真实目录），
  外加系统原生的目录选择对话框
- 选择器里的**每一项都是真的**：agent 是解析得到的，目录候选是索引里真实存在的路径

**不在本次范围**：工作集与持久化（D-5 / D-6）、批量恢复（D-12）、会话摘要（D-7）。

## Capabilities

### New Capabilities
- `session-launch`: 判定哪些 agent 在本机可用、从会话索引里给出目录候选

### Modified Capabilities
- `app-shell`: 新增「新建会话」选择器 —— 原规格完全没有定义这个按钮的行为

## Impact

- 无新增依赖。目录选择用 Electron 自带的 `dialog.showOpenDialog`
- 新增 `src/main/sessions/launch.ts`（纯函数：可用 agent 判定、目录候选）
- 复用 `terminal-host` 的 `spawnManaged` 与 `resolveCommand`，不新增启动路径
