## ADDED Requirements

### Requirement: 只呈现本机真正可用的 agent

系统 SHALL 通过实际解析可执行文件来判定 agent 是否可用，
SHALL NOT 呈现无法解析的 agent。

列出一个装不上的 agent、让用户选了之后才失败，是又一个界面上的假承诺。

#### Scenario: 未安装的 agent 不出现

- **WHEN** 某个 agent 无法解析成可执行文件
- **THEN** 它不出现在可选列表中

#### Scenario: 判定基于真实解析而非硬编码

- **WHEN** 判定可用性
- **THEN** 用的是与启动时相同的解析逻辑
- **AND** 因此「列表里有」等价于「一定能启动」

#### Scenario: 一个都没有时说明原因

- **WHEN** 五个 agent 一个都解析不出
- **THEN** 返回空列表，界面明确说明未检测到任何 agent
- **AND** 不显示成空白或加载中

### Requirement: 工作目录候选来自真实会话索引

系统 SHALL 从已索引的会话中提取工作目录作为候选，
SHALL NOT 呈现任何不存在的目录。

#### Scenario: 候选去重且按最近使用排序

- **WHEN** 多个会话共用同一个工作目录
- **THEN** 该目录在候选中只出现一次
- **AND** 候选按该目录上最近一次会话活动时间倒序

#### Scenario: 已消失的目录不作候选

- **WHEN** 某个会话的工作目录已不存在
- **THEN** 该目录不出现在候选中
- **AND** 这与历史视图不同 —— 历史是回顾，候选是要拿去启动的

#### Scenario: 工作目录未知的会话不贡献候选

- **WHEN** 某条会话的 `cwd` 为 null
- **THEN** 它不贡献任何候选

### Requirement: 拒绝在不存在的目录下新建

系统 SHALL 在启动前校验目标目录存在，SHALL NOT 自动创建它。

用户手输路径时打错字是常态。悄悄建一个目录、然后在里面开一个空会话，
比直接报错糟糕得多。

#### Scenario: 目录不存在

- **WHEN** 请求在一个不存在的目录下新建会话
- **THEN** 拒绝并给出指明该路径的错误
- **AND** 不创建该目录

#### Scenario: 路径指向的是文件

- **WHEN** 给出的路径存在但不是目录
- **THEN** 同样拒绝并说明
