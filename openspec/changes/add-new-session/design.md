## Context

「新建会话」按钮从 `add-app-shell` 起就存在于界面上，但**从未被实现，也从未被规格定义**。
用户点它时才暴露。

这是本项目到目前为止**最该被规格审查抓住却没抓住**的一个问题：
`add-app-shell` 的规格写了「侧栏不得展示占位或虚构会话」「未实现的功能必须如实标注」，
却漏了它自己界面上的一个死按钮。教训是：**规格要覆盖界面上出现的每一个控件**，
而不只是覆盖有数据的那些区域。

## Goals / Non-Goals

**Goals:**
- 把假按钮变成真的：选 agent + 选目录 + 起会话
- 选择器里**每一项都是真的** —— agent 是解析出来的，目录候选是索引里真实存在的
- 纯逻辑（可用性判定、目录候选）严格 TDD

**Non-Goals:**
- 工作集与持久化、批量恢复、摘要
- 不记「上次用的 agent/目录」—— 那属于设置持久化，等工作集那一刀一起做

## Decisions

### D-N1 · 可用性判定复用启动时的同一套解析

用 `terminal-host` 的 `resolveCommand`。**「列表里有」必须等价于「一定能启动」** ——
两套判定迟早会分叉，那时列表里就会出现启动即失败的项，又是一个假承诺。

判定函数接受一个解析器作为参数，测试可注入，不依赖本机装了哪些 agent。

### D-N2 · 目录候选来自会话索引，且**排除已消失的目录**

索引里有 437 条会话、数十个真实目录 —— 这是现成的、真实的候选来源，
比让用户每次都去浏览要顺手得多。

**与历史视图的处理刻意不同**：历史视图保留 `cwdExists=false` 的会话（那是回顾，
用户的历史不该被藏起来），而候选**排除**它们（那是要拿去启动的，给一个不存在的目录毫无意义）。

### D-N3 · 目录用系统原生对话框，不自绘

`dialog.showOpenDialog({ properties: ["openDirectory"] })`。
自绘文件浏览器要处理盘符、权限、符号链接、网络路径 —— 平台已经做好了。
同 D-2「买来的黑盒」的精神。

### D-N4 · 拒绝不存在的目录，绝不自动创建

手输路径打错字是常态。悄悄 `mkdir` 然后在里面开一个空会话，
用户会以为自己进错了项目 —— 比直接报错糟糕得多。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 可用性判定要跑 5 次 `where.exe`，可能慢 | 实测记录耗时；只在打开选择器时判一次，不每帧判 |
| 目录候选可能很多（本机数十个） | 用 `<datalist>` 让浏览器自己做前缀过滤，不自己写下拉 |
| 选择器又是一段没有自动化测试的界面 | 纯逻辑（可用性、候选）严格 TDD；界面靠冒烟 + 真机验收，同 `add-app-shell` 的取舍 |

## Open Questions

- 是否记住「上次用的 agent 与目录」？倾向记 —— 用户多半在少数几个目录间轮换。
  但那需要设置持久化，留到工作集那一刀。
