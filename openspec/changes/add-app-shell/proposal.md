## Why

`prototype-terminal-fidelity` 交付了两件事：终端能跑（`terminal-host`）、主题能换（`theme-system`）。
但它的界面是**一个占满窗口的裸终端**，外加两个快捷键切主题 —— 没有 explorer、没有 tab、没有设置界面。

两个问题：

1. **D-1 的形态没有落地。** 用户的核心痛点是「多个 agent 之间怎么切换」，
   而切换的载体（左侧 explorer + 顶部 tab）根本不存在。
2. **窗口观感陈旧。** 用的是 Windows 默认标题栏，与用户给出的对标（Claude 桌面版）差距明显。
   用户原话：「希望对标的感觉是 claude desktop 版本」。

同时 `theme-system` 只完成了一半：主题能切，但**只能靠快捷键**，
用户明确要求「有设置窗口，窗口里有各种主题的小 demo 那种感觉」。

## What Changes

- **自绘标题栏**：藏掉系统标题栏，改为应用自己的顶栏 ——
  左侧品牌标识、中间标签页；原生的最小化/最大化/关闭用 `titleBarOverlay` 贴进来，
  保留系统行为（拖拽贴边、Snap、双击最大化）的同时**跟随主题换色**
- **左侧工作集栏**：新建会话入口、按**真实 cwd** 分组的会话树（每行含 agent、运行状态、摘要位）、
  底部状态与设置入口
- **顶部标签页**：每个会话一个，显示 agent 与文件夹名，含运行状态圆点
- **设置弹窗**：明暗分段控件 + 主题卡片网格，**每张卡片内是一个微缩的应用截面**
  （侧栏 + 终端内容，用该主题自己的颜色），而不是一排色块
- 全部样式走 `theme-system` 注入的 `--c-*` 变量，**CSS 中不出现硬编码色值**

**不在本次范围**：多会话（目前只显示应用起的那一个）、会话摘要（D-7，未实现，
界面上如实显示「摘要功能还没做」而不是编一句假的）、历史会话搜索、工作集持久化、批量恢复。

## Capabilities

### New Capabilities
- `app-shell`: 应用窗口外壳 —— 自绘标题栏与原生窗口控件的集成、
  工作集侧栏、标签页、设置弹窗，以及它们与主题的联动

### Modified Capabilities
- `theme-system`: 新增「通过界面选择主题与明暗」的要求。
  原规格只定义了主题的加载、解析与应用，未规定用户如何选择

## Impact

- 无新增依赖
- `src/renderer/` 重构：`index.html` 换成外壳结构，新增 `shell.ts`，`style.css` 重写
- `src/main/index.ts`：`titleBarStyle: "hidden"` + `titleBarOverlay`，
  新增 `window:overlay` IPC 供渲染层回传主题色（变体解析在渲染层）
- `src/preload/index.ts`：新增 `setWindowOverlay`
- **顶栏高度在两处定义**：主进程的 `TITLEBAR_HEIGHT` 与 CSS 的 `--titlebar-h` 必须一致，
  否则原生窗口控件会错位。已在两处互相注明
